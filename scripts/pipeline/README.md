# 데이터 파이프라인

앱 소스(`src/`)와 분리된 데이터 생성·가공 스크립트 모음.
앱 빌드에는 포함되지 않으며, 단어 데이터를 추가·수정할 때만 사용한다.

## 구성

| 스크립트 | 용도 |
|---|---|
| `generate-tts.mjs` | 단어 발음 mp3 일괄 생성 (Google Cloud TTS Neural) |

## 발음 mp3 생성

```bash
GOOGLE_TTS_API_KEY=<키> npm run tts:generate
```

- 소스: `src/data/words/*.ts` (일본어), `src/data/korean-words*.ts` (한국어)
- 출력: `public/audio/<lang>/<id>.mp3` — id는 `fnv1a(expression|reading)`
  (`src/utils/wordAudio.ts`의 해시와 반드시 동일해야 함)
- 이미 생성된 파일은 건너뛰므로 **단어 추가 후 재실행하면 신규분만 생성**됨
- 실패 시 `tts-failures.json`에 기록되고, 재실행하면 실패분만 재시도
- 속도 제한: 분당 약 160건 (429 시 지수 백오프 재시도)

### API 키 발급 (필요할 때마다)
1. console.cloud.google.com → Cloud Text-to-Speech API 활성화
2. 사용자 인증 정보 → API 키 생성 (애플리케이션 제한 "없음", API 제한 "TTS만")
3. 사용 후 키 삭제 권장. 전체 재생성해도 무료 한도(월 100만 자)의 ~3% 수준

## ⚠️ 일본어 TTS 입력 규칙 (오독 방지)

TTS 엔진은 입력 텍스트를 **형태소 분석**해서 읽는다 — 그래서 무엇을 보내느냐가 발음을 바꾼다.
`generate-tts.mjs` 의 `ttsInput()` 이 지키는 규칙:

| 입력 | 언제 | 이유 |
|---|---|---|
| **한자 표기 (기본)** | 표기에 대응하는 읽기가 하나뿐일 때 | 사전 기반이라 악센트가 정확하다 |
| **가나 읽기** | 같은 표기에 읽기가 여럿일 때 (`一日` = いちにち/ついたち 등 68개) | 한자로 보내면 TTS 가 다른 읽기로 읽어버린다 |

### ⛔ 어두 조사 가나 오독 (2026-08-04 확인)

`は`·`へ`·`を` 는 **조사일 때 각각 「와」·「에」·「오」로 읽힌다**. 가나만으로 된 짧은 단어를
그대로 보내면 분석기가 **어두의 `は` 를 조사로 잘라내 "하" 를 "와" 로 발음**한다.

- 한자로 보내는 단어는 안전하다 (읽기가 `は` 로 시작하는 144개 — `花`·`始まる`·`八` 등 정상)
- **가나로 보내는 단어만 노출**된다: `は` 시작 9개(`はず`·`はし`·`はく`·`はあ`·`はい`·
  `はっきり`·`はさみ`·`はじめに`·`はきはき`), `へ` 시작 1개(`へん`)

**대응**: 가나만으로 된 단어를 새로 추가하면 **생성 후 반드시 들어볼 것**
(`afplay public/audio/ja/<id>.mp3`). 오독이면 `ttsInput()` 에 예외를 넣는다 —
가타카나(`はず`→`ハズ`, 조사로 쓰이지 않아 조사 해석이 불가능) 또는 해당 뜻의 한자
(`はく`→`履く`)로 바꾸고, 바꾼 뒤에도 다시 들어서 억양이 자연스러운지 확인한다.

> mp3 는 한 번 구워지면 그대로 배포되므로 **이 확인을 건너뛰면 오독이 그대로 나간다.**
> 이미 만들어진 파일은 재생성 대상에서 제외되니, 고칠 때는 해당 mp3 를 먼저 지운다.

### 폴백 경로는 항상 가나로 읽는다 (mp3 없을 때)

mp3 를 못 찾으면 `src/utils/speech.ts` 의 Web Speech 폴백이 동작하는데, 이쪽은
`reading || text` — 즉 **항상 가나**를 보낸다. 그래서 mp3 가 없는 상태에서는
읽기가 `は` 로 시작하는 단어 전체(144개, `花`·`始まる`·`八`·`葉書` 등)가
어두 조사 오독에 노출된다. mp3 가 있으면 한자로 읽히므로 문제가 없다.

- **mp3 커버리지가 100% 인지 항상 확인할 것** (위 sync-contract 검증 명령)
- 구버전 앱(mp3 포함 이전 빌드)을 설치한 기기에서는 이 폴백이 동작하므로,
  단어 데이터·mp3 를 갱신했으면 **기기 앱도 재설치**해야 발음이 고쳐진다

## 단어 데이터 추가 절차

1. `src/data/` 의 해당 파일에 단어 추가 (형식: `{ expression, reading?, meanings: { en, ko?/ja? }, lang, level }`)
2. `npx tsc --noEmit` 통과 확인
3. `npm run tts:generate` 로 신규 단어 mp3 생성
4. **가나만으로 된 일본어 단어를 추가했다면 발음 청취 확인** (위 오독 규칙)
5. `npm run build:ios` 로 iOS 반영
