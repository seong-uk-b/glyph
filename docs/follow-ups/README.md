# Follow-ups — 추후 조치 항목

지금 당장은 하지 않지만 잊지 말아야 할 작업을 모아두는 곳.

## 룰

1. **위치**: `docs/follow-ups/{YYYY-MM-DD}-{kebab-case-topic}.md`
   - 날짜 prefix 로 시간순 정렬
   - 한 토픽 = 한 파일

2. **파일 구조** (권장):
   ```markdown
   # {제목}

   **상태**: open | in-progress | done | dropped
   **우선순위**: P0 (긴급) | P1 (높음) | P2 (보통) | P3 (낮음)
   **예상 공수**: ~30분 / ~2h / ~1d / 등
   **의존성**: 다른 follow-up 또는 외부 결정 대기

   ## 문제

   현 상태에서 무엇이 잘못/부족한가.

   ## 원인 분석

   왜 그런지. 측정값 / 로그 / 코드 위치 포함.

   ## 제안 (스텝별)

   1. ...
   2. ...

   각 스텝마다: 작업 내용 + 영향 받는 파일 + 검증 방법.

   ## 리스크 / 트레이드오프

   ## 참고

   - 관련 코드 경로
   - 관련 이슈/PR
   ```

3. **인덱스 등록**: 작성 후 이 README 하단 "현재 열린 항목" 에 한 줄 추가 —
   미래 세션에서 발견 가능하게. (형식: 링크 — 한 줄 요약 + 상태)

4. **완료 시 처리**: 상태 `done` 표기 후 파일 삭제. 인덱스를 열린 항목만
   깔끔히 유지하는 것을 우선한다.
   - ⚠️ **이 디렉토리가 git 에 추적되는지 먼저 확인하라** (`git check-ignore docs/follow-ups` 가
     아무것도 출력하지 않아야 정상). **untracked 파일 삭제는 git 으로 복구 불가** —
     지우기 전 핵심 내용을 관련 추적 문서에 흡수했는지 확인할 것.
   - 보존이 꼭 필요하면 `archive/` 하위로 이동.
