# Agent Harness

이 디렉토리는 **새 에이전트 세션이 채팅 히스토리 없이 저장소 파일만으로 작업을
이어받을 수 있게** 하는 하네스다. 패턴 출처는 harness-engineering
(https://openai.com/index/harness-engineering/).

루트 `CLAUDE.md` 가 **워크플로우 룰의 정본**이고,
이 디렉토리는 그 위에 **세션 연속성**(상태 핸드오프 + 검증 증거)을 얹는다.
두 문서가 충돌하면 CLAUDE.md 가 이긴다.

## 파일

- `README.md` — 이 파일. 운영 모델과 지식 규칙, 알려진 한계.
- `session-state.md` — 활성 트랙 **인덱스** (표만; 트랙 상세는 `{트랙}.md` 단위 파일).
- `{트랙}.md` — 트랙별 핸드오프 상태 (계속 덮어씀).
- `verification.md` — 완료 주장을 증명하는 명령 모음 + 기능별 스모크 체크리스트 (누적).
- `sync-contracts.md` — "X 바뀌면 같은 커밋에서 Y·Z" 동반갱신 계약 레지스트리.
- `STYLE.md` — 룰·정본 문서 작성 규범 (단일 소유·⛔ 마커·재스코프).

세션 의식(스킬)은 레포 루트 기준 `.claude/skills/{kickoff,handoff}/SKILL.md`,
하네스 린트는 `scripts/harness-check.sh` 에 있다.

## 기존 문서와의 분업 (중복 기록 금지)

| 위치 | 역할 | 성격 |
|---|---|---|
| `docs/harness/{트랙}.md` | **지금 진행 중인 것**의 스냅샷 — 브랜치·커밋·검증 증거·다음 행동 | 계속 덮어씀 |
| `docs/follow-ups/` | **나중에 할 일** — 지금 안 하지만 잊지 말아야 할 작업 | 불변 스펙, 완료 시 인덱스 갱신 |
| 루트 `CLAUDE.md` + `ARCHITECTURE.md` | 프로젝트 룰·설계 | 정본 |
| 에이전트 개인 auto-memory | 개인 컨텍스트 (선호·교훈) | git 밖, 로컬 전용 |

같은 내용을 두 곳 이상에 쓰지 않는다. 트랙 파일은 follow-up/spec 을
**가리키기만** 한다 (내용 복제 금지).

## 운영 모델

1. **Kickoff**: 세션 시작 시 `/kickoff {트랙}` 으로 그 트랙 파일만 로드하고 시작한다.
2. 행동을 바꾸는 작업은 문서화된 spec/plan 에서 출발한다.
3. 작고 검증 가능한 변경을 선호한다.
4. **완료 주장 = 검증 증거.** "다 됐다"는 말은 `verification.md` 의 해당 명령을
   이 세션에서 **fresh run** 한 결과를 첨부해야 성립한다.
5. **Handoff**: 긴 세션을 끝내기 전 트랙 파일을 갱신하고 커밋한다 (`/handoff`).
6. 반복되는 지시는 docs / tests / scripts / skills 로 인코딩한다.

## 지식 규칙

- 미래 세션이 알아야 하면 **저장소에** 넣는다 (채팅 메모리·로컬 상태에 의존 금지).
- 지시가 길어지면 CLAUDE.md 에서 빼서 이 디렉토리나 전용 spec 으로 옮긴다.
- 반복 실수를 막는 룰은 가능하면 기계적으로 체크 가능하게 만든다.
- 트랙 파일 갱신 시 어떤 도구(Claude Code 등)로 작업했는지 기록한다.

## 알려진 한계 (이 체계가 보장하지 않는 것)

이 한계들은 기계가 막아주지 않는다 — 아래 보완 룰로 운영한다.

1. **handoff 없이 끝난 세션의 상태는 유실된다** (크래시·컨텍스트 고갈·그냥 종료).
   보완: 중간 상태가 중요해지는 시점마다 수시로 커밋하고, 긴 작업은 트랙 파일을
   세션 중간에도 갱신한다. 다음 kickoff 는 트랙 파일을 "마지막 관측"으로만 취급한다.
2. **동시성 제어가 없다.** 두 세션이 같은 트랙(또는 인덱스)을 동시에 handoff 하면
   마지막 쓰기가 이긴다. 보완: **트랙당 동시 세션은 하나** — 병행 작업은 트랙을
   분리하고, worktree 로 격리했다면 인덱스 병합 충돌을 handoff 때 사람이 확인한다.
3. **브랜치 가드는 ask 이지 완전 차단이 아니다.** alias(`git co`)·따옴표 내부 실행은
   감지하지 못한다. 보완: 룰(CLAUDE.md §1)이 정본이고 가드는 안전망일 뿐이다.
4. **트랙 파일 기록은 낡을 수 있다.** 기록된 "검증 통과"는 그 세션의 사실이지 현재의
   사실이 아니다. 보완: fresh run 정책 (verification.md).
